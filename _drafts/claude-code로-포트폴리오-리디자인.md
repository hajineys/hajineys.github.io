## 뭘 했나

기존 Jekyll(Chirpy 테마) 포트폴리오 사이트를 Claude Code랑 같이 하루 만에 갈아엎었다.

- 왼쪽 사이드바(테마 토글, 소셜 아이콘) 제거 → 상단바로 통합
- 오른쪽 카테고리 패널 제거 → HOME/ABOUT 내비게이션은 상단바로 이동
- 다크/라이트/시스템 테마 토글 제거 → 라이트로 고정
- 홈 히어로를 "블루프린트 스펙시트" 스타일로 재설계
- 실제 경력(PawPop Match, Space Gears, 아머드 사우루스) 기반 콘텐츠로 교체
  - 예전엔 "제조 AX / ROS / 디지털 트윈" 같은 레이아웃 테스트용 가짜 콘텐츠가 들어있었음
- 프로젝트별 상세 페이지(`/projects/*`) 추가
- 홈 화면을 Posts / Featured Projects 2단 레이아웃으로 재구성, 두 리스트 디자인 통일

## 가장 까다로웠던 부분: 서비스워커 캐시

사이트에 PWA(오프라인 캐싱)가 기본으로 켜져 있었는데, 이게 개인 블로그처럼 자주 바뀌는 사이트엔 안 맞았다.

- `_config.yml`의 `pwa.enabled: false`만 끄면 될 줄 알았는데, 그러면 기존 방문자 브라우저에 남아있는 서비스워커를 정리해주는 스크립트(`app.min.js`)까지 같이 안 실행돼서 **예전 캐시가 영영 안 지워지는 문제**가 있었음
- 테마 소스(`head.html`)까지 까봐서 확인: `pwa.enabled: true` + `pwa.cache.enabled: false` 조합이어야 정리 스크립트가 로드되면서 `swconf.purge: true`가 켜짐
- 근데 이것도 100% 확실한 방법은 아니었음 — 서비스워커 자체 파일(`sw.min.js`)이 배포마다 바이트가 안 바뀌는 구조라, 브라우저가 "업데이트 있음"을 확률적으로만 감지함 (spec상 importScripts로 불러오는 하위 파일은 업데이트 감지 대상이 아님)
- 최종 해결: `assets/js/dist/sw.min.js`를 직접 오버라이드해서 빌드 시각을 주석으로 박아넣음 → 배포할 때마다 파일 바이트가 무조건 달라지게 만들어서, 업데이트 감지를 "확률"이 아니라 "확정"으로 바꿈
- Jekyll 테마는 사이트 쪽 파일이 gem(테마) 파일보다 우선순위가 높다는 걸 이번에 알게 됨 — 그래서 이런 오버라이드가 가능했음

## 그 외 배운 것

- `_config.yml` 바꾸면 `jekyll serve`는 껐다 켜야 반영됨 (파일 watch 대상이 아님)
- GitHub Pages 배포는 push하면 Actions가 알아서 빌드/배포, `gh` CLI 없어도 `curl`로 Actions API 찔러서 배포 상태 확인 가능
- 로컬 PC는 그냥 작업용 사본, 실제 서빙은 GitHub이 다 해줌 (무료)
